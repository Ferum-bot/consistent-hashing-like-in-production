# consistent-hashing-like-in-production

Стенд для шардирования сервиса кошельков. Роутер раскладывает пользователей по нодам через `hash % N` или кольцо consistent hashing. Loadgen нагружает кластер и проверяет, что деньги не теряются. Метрики собирает Prometheus, дашборд — в Grafana.

## Что где лежит

| Папка | Что внутри |
| --- | --- |
| `services/wallet` | сервис кошельков, хранит пользователей в памяти |
| `services/router` | роутер перед нодами: стратегии шардирования, перенос данных, защита по версии топологии |
| `services/loadgen` | генератор нагрузки и сверка балансов |
| `services/libs` | общий код: стратегии шардирования, запуск сервиса, конфиг, HTTP-помощники, чтение снапшота |
| `tools/chctl` | пульт: топология, загрузка данных, нагрузка |
| `tools/datagen` | генератор снапшота пользователей |
| `scenarios` | готовые конфигурации стенда, по одной папке на сценарий |
| `infra` | Prometheus, Grafana и таблица портов |
| `data` | снапшот пользователей, создаётся `task data`, в git не попадает |

У каждой папки свой README с подробностями.

## Что нужно

Go 1.26, Docker с compose и [Task](https://taskfile.dev).

## Запуск

Один раз: собрать образы и сгенерировать 2 млн пользователей.

```bash
task build
task data
```

Поднять кластер, разложить данные и включить нагрузку. Loadgen поднимается на паузе и начинает слать запросы только после `task load:apply`:

```bash
task fresh -- 01-mod-3
task load:apply -- 01-mod-3
```

`task fresh` поднимает сценарий на чистых данных, `task scenario` — только меняет топологию. Дальше сценарии переключаются командой `task scenario -- <папка из scenarios>`. Какие есть сценарии и как между ними ходить — в [scenarios/README.md](scenarios/README.md).

| Что | Где |
| --- | --- |
| Grafana | http://localhost:3000 |
| Роутеры | http://localhost:8081, http://localhost:8082 |
| wallet | http://localhost:9001 … 9005 |
| loadgen | http://localhost:8090 |

По корню каждого сервиса открывается Swagger. Остальные порты — в [infra/README.md](infra/README.md).

Что сейчас поднято, на какой топологии роутеры и сколько данных на нодах:

```bash
task status
```

Остановить всё:

```bash
task down
```

## Разработка

```bash
task test
task vet
task build
```

`task build` нужен после любых изменений в коде: сценарии сами образы не пересобирают. Список всех команд — `task --list`.

## Вопросы

Вопросы, ошибки и идеи — в [Issues](https://github.com/Ferum-bot/consistent-hashing-like-in-production/issues). При создании выбери шаблон: ошибка, вопрос или предложение — в нём уже есть поля для сценария, команд и вывода.

## Как предложить изменения

Доступ к репозиторию для этого не нужен: изменения предлагаются через fork и pull request.

1. Нажми **Fork** на странице репозитория — у тебя появится своя копия.
2. Склонируй её и создай ветку под изменение:

   ```bash
   git clone https://github.com/<твой-логин>/consistent-hashing-like-in-production.git
   cd consistent-hashing-like-in-production
   git checkout -b fix-ring-lookup
   ```

3. Внеси изменения и проверь их:

   ```bash
   task test
   task vet
   ```

   Если менялся код сервисов, пересобери образы (`task build`) и прогони нужный сценарий.
4. Отправь ветку в свой fork и открой pull request в ветку `main` этого репозитория. В описании напиши, что и зачем поменялось и как это проверить.

Одно изменение — один pull request. Если правка большая или меняет поведение стенда, лучше сначала обсудить её в issue.
