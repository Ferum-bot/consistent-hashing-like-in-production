# loadgen

Генератор нагрузки. Изображает клиентов кошельков: читает, пополняет и списывает через оба роутера.

Заодно проверяет, что деньги не теряются. При старте loadgen читает тот же снапшот, что разложен по кластеру, и ведёт книгу ожидаемых балансов: каждое успешное пополнение и списание меняет её. Каждое чтение сверяется с книгой.

После запуска стоит на паузе.

## Нагрузка

| Параметр | По умолчанию | Что значит |
| --- | --- | --- |
| `running` | `false` | идёт ли нагрузка |
| `rps` | 1000 | операций в секунду |
| `read_ratio` | 0.7 | доля чтений, остальное — записи |
| `deposit_share` | 0.5 | доля пополнений среди записей, остальное — списания |
| `read_zipf_s` | 0 | перекос чтений: 0 — все пользователи равновероятны, больше 1 — есть горячие |
| `write_zipf_s` | 1.1 | перекос записей, так же |
| `hot_share` | 0.05 | доля записей в одного мерчанта |
| `merchant_user_id` | 1000000 | кто мерчант; если в снапшоте меньше пользователей, `hot_share` не действует |
| `max_amount` | 10000 | максимальная сумма операции |
| `verify_rps` | 50 | сколько раз в секунду перепроверять недавно изменённых пользователей |

Всё меняется на лету, без перезапуска.

## Сверка

| Результат | Что значит |
| --- | --- |
| `ok` | сервис вернул то, что ожидалось |
| `missing` | сервис ответил 404, а пользователь существует |
| `lost` | денег на сервисе меньше, чем должно быть |
| `extra` | денег на сервисе больше, чем должно быть |
| `skipped` | сверять нельзя: по пользователю шла запись, результат прошлой записи неизвестен или роутер ответил не 200 и не 404 |

Если запрос оборвался или роутер ответил 5xx, неизвестно, прошла ли операция, и пользователь больше не сверяется. Исключение — 503: роутер отвечает им, когда не стал отправлять запрос на ноду, так что операция точно не прошла. Сколько таких — видно в `/ledger`.

## Ручки

| Ручка | Что делает |
| --- | --- |
| `GET /config` | текущие параметры нагрузки |
| `PATCH /config` | поменять параметры, передаются только нужные поля |
| `GET /ledger` | сколько пользователей и денег в книге |
| `POST /ledger/reload` | перечитать снапшот |
| `GET /healthz` | жив ли процесс |
| `GET /metrics` | метрики Prometheus |

Swagger — на `/swagger/`, корень `/` ведёт туда же.

## Запуск

Loadgen поднимается вместе со сценарием (`task scenario`) и ждёт на паузе. Когда данные загружены, включить нагрузку из файла сценария. Все команды `task load:*` запускаются из корня репозитория:

```bash
task load:apply -- 01-mod-3
```

В Docker loadgen доступен на `localhost:8090`, при локальном запуске через `task run` слушает `:8080` из `config.yaml`.

Параметры запуска в `config.yaml`, их можно перекрыть переменными окружения `ADDR`, `TARGETS` (роутеры через запятую), `SNAPSHOT_PATH`, `WORKERS` и `REQUEST_TIMEOUT`. Параметры нагрузки из `profile` меняются на лету через `/config`.

Поменять нагрузку:

```bash
task load:set -- rps=3000
task load:set -- read_zipf_s=1.2 write_zipf_s=1.3 hot_share=0.1
task load:set -- running=false
task load:status
```

После `task reset` и `task bootstrap` книгу надо перечитать, иначе каждая сверка покажет расхождение. `task fresh` делает это сам:

```bash
task load:reload
```
