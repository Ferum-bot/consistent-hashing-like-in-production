# datagen

Генерирует пользователей с кошельками для стенда. Результат — файл `data/snapshot.ndjson`, по одному пользователю на строку, в том же формате, что отдаёт `GET /export` у wallet.

Из этого файла роутер раскладывает пользователей по нодам (`task bootstrap`), а loadgen берёт ожидаемые балансы для сверки.

У каждого пользователя от 1 до 5 кошельков в разных валютах со случайным балансом. При одном и том же `-seed` файл получается одинаковым.

## Запуск

Из корня репозитория:

```bash
task data
task data -- -users 100000
```

Из `tools` или `tools/datagen`:

```bash
task datagen
task datagen -- -users 100000
```

Файл по умолчанию пишется в `data/snapshot.ndjson` в корне репозитория.

## Флаги

| Флаг | По умолчанию | Что значит |
| --- | --- | --- |
| `-users` | 2000000 | сколько пользователей |
| `-max-wallets` | 5 | сколько кошельков максимум у одного пользователя |
| `-max-balance` | 1000000 | максимальный баланс кошелька в минимальных единицах валюты |
| `-seed` | 1 | зерно генератора |
| `-out` | `../data/snapshot.ndjson` | куда писать |

Если меняешь число пользователей:

- поменяй `users` у роутера — по нему он считает ожидаемую долю пользователей на ноду. Локально это `services/router/config.yaml`, в Docker — добавить роутерам переменную `USERS` в `services/router/compose.yaml`, потому что `config.yaml` вшит в образ;
- мерчант loadgen — пользователь `1000000`. Если пользователей меньше, записи мерчанту не отправляются, пока не поменять `merchant_user_id`: `task load:set -- merchant_user_id=100`.
