# chctl

Пульт управления стендом. Через него применяется топология кластера, загружаются данные и меняется нагрузка.

## Команды

| Команда | Что делает |
| --- | --- |
| `status` | показывает, что поднято: роутеры и их топологию, ноды wallet, loadgen |
| `apply <файл>` | отправляет топологию на все роутеры, с переносом данных, если в файле `"migrate": true` |
| `abort` | откатывает незаконченный перенос на всех роутерах |
| `cleanup` | доделывает прерванный перенос: ждёт, пока переключатся все роутеры, и удаляет старые копии |
| `bootstrap` | раскладывает пользователей из снапшота по нодам текущей топологии |
| `import [url]` | загружает пользователей из снапшота напрямую в один процесс wallet, без роутера |
| `load status` | показывает параметры нагрузки и книгу балансов loadgen |
| `load set key=value ...` | меняет параметры нагрузки, например `running=true rps=2000` |
| `load apply <файл>` | меняет параметры нагрузки из файла |
| `load pause` | ставит нагрузку на паузу, если loadgen поднят; если нет — ничего не делает |
| `load reload` | заставляет loadgen перечитать снапшот |

Первый роутер из `-routers` — координатор. Через него идут `bootstrap`, копирование и уборка при переносе, остальные роутеры только переключают топологию.

`apply` сам присваивает топологии версию: берёт самую большую у роутеров и прибавляет единицу. Поэтому все роутеры получают одинаковый номер. Версию в файле писать не нужно, а неизвестные поля в файле считаются ошибкой.

Перенос с `"migrate": true` идёт по фазам:

1. `prepare` на всех роутерах;
2. `migrate` на первом;
3. `commit` на всех;
4. ожидание, пока все роутеры переключатся;
5. `cleanup` на первом.

Старые копии удаляются только после того, как на новую топологию перешли все: иначе отстающий роутер писал бы в удалённые данные. Время каждой фазы печатается. Если перенос сорвался до `commit`, роутеры откатываются на текущую топологию. Если у роутеров ещё нет топологии, переносить нечего, и `apply` применяет её сразу.

## Когда что-то не так

chctl не падает с сырой сетевой ошибкой, а говорит, что случилось и что сделать. Подсказки называют команды chctl, в Task им соответствуют задачи из корня: `task abort`, `task load:reload` и так далее.

| Ситуация | Что делает chctl |
| --- | --- |
| стенд не поднят | `status` показывает `down` у каждого сервиса, остальные команды подсказывают поднять сценарий |
| сервисы только стартуют | `apply` и `load apply` ждут до минуты, пока роутеры или loadgen начнут отвечать |
| у роутеров нет топологии | `status` пишет `no topology yet`, `bootstrap` подсказывает применить сценарий |
| нет снапшота | `import`, `bootstrap` и `load reload` подсказывают сгенерировать его через datagen |
| книга loadgen не загружена | `load status` подсказывает `chctl load reload` |
| незаконченный перенос | `status` показывает `migrating to vN`, `apply` отказывается и подсказывает `chctl abort` |
| отстающий роутер не смог применить изменение | `status` показывает причину, `apply` не ждёт впустую, а сразу печатает её |
| перенос прервался на ожидании роутеров | старые копии остаются, `apply` подсказывает `chctl cleanup` |
| роутеры на разных версиях | `status` показывает версию каждого и отмечает расхождение |
| роутер перезапустился и потерял топологию | `apply` сначала отдаёт ему текущую топологию самого нового роутера, потом применяет новую |

Коды выхода: 0 — успех, 1 — команда не выполнилась, 2 — неверные аргументы.

## Запуск

Команды зависят от папки, из которой запускаешь.

Из корня репозитория — готовые задачи Task:

```bash
task scenario -- 01-mod-3
task fresh -- 01-mod-3
task status
task bootstrap
task abort
task cleanup
task import -- http://localhost:9001
task load:apply -- 01-mod-3
task load:set -- rps=2000
task load:status
task load:reload
```

Из `tools` или `tools/chctl` — любая команда chctl через `task chctl`, всё после `--` уходит в chctl. Пути считаются от папки `tools`:

```bash
task chctl -- status
task chctl -- apply ../scenarios/01-mod-3/topology.json
task chctl -- bootstrap
task chctl -- import -limit 10000 http://localhost:8080
task chctl -- load set rps=2000
task chctl -- load status
```

Без Task, из папки `tools`:

```bash
go run ./chctl status
go run ./chctl apply ../scenarios/01-mod-3/topology.json
```

`import` грузит снапшот в один wallet, адрес по умолчанию — `http://localhost:8080`. Флаги:

| Флаг | По умолчанию | Что значит |
| --- | --- | --- |
| `-snapshot` | `../data/snapshot.ndjson` | откуда брать пользователей |
| `-limit` | 0 | загрузить только первых N, 0 — всех |
| `-batch` | 5000 | сколько пользователей в одном запросе |

Импорт заменяет пользователя целиком, поэтому повторный запуск не задваивает данные.

Адреса по умолчанию — роутеры на `localhost:8081` и `localhost:8082`, ноды wallet на `localhost:9001` … `9005`, loadgen на `localhost:8090`. Поменять можно флагами `-routers`, `-wallets` и `-loadgen`, списки — через запятую. Ноды нужны только для `status`.

## Устройство

| Где | Что |
| --- | --- |
| `main.go` | флаги, выбор команды, коды выхода |
| `commands/command.go` | описание команды и список всех команд |
| `commands/<команда>.go` | по файлу на команду: `status`, `apply`, `abort`, `cleanup`, `bootstrap`, `import`, `load` |
| `commands/migrate.go` | фазы переноса для `apply` |
| `commands/topology.go` | чтение файла топологии и описание топологии для вывода |
| `commands/wait.go` | ожидание, пока сервис начнёт отвечать |
| `commands/hints.go` | подсказки к ошибкам |
| `client/` | клиенты к router, wallet и loadgen и фабрика `Factory`, которая их создаёт; ошибки `UnreachableError` и `ResponseError` |

Команды не собирают HTTP-запросы: они вызывают методы клиентов и печатают результат. Клиенты не знают про вывод и подсказки.

Новая команда — это файл в `commands/` с переменной `Command` (имя, аргументы, описание, функция запуска) и строка в `List()`. Справка собирается из этого списка сама.
