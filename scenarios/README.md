# scenarios

Готовые конфигурации стенда. Одна папка — один сценарий, в ней всё, что для него нужно:

| Файл | Что задаёт |
| --- | --- |
| `compose.yaml` | какие процессы запущены |
| `topology.json` | как роутеры раскладывают пользователей по нодам, если в сценарии есть роутеры |
| `load.json` | с какой нагрузкой работает loadgen |

| Сценарий | Что внутри |
| --- | --- |
| `00-monolith` | один wallet, loadgen ходит в него напрямую |
| `01-mod-3` | 5 нод wallet, 2 роутера, пользователи раскладываются по трём нодам через `hash % 3` |
| `02-mod-4` | тот же кластер, `hash % 4` на четырёх нодах |
| `03-ring-3` | тот же кластер, кольцо по одной точке на ноду, три ноды |
| `03-ring-4` | то же кольцо, добавлена четвёртая нода |
| `04-ring-4`, `04-ring-16`, `04-ring-64`, `04-ring-256` | кольцо на четырёх нодах с 4, 16, 64 и 256 точками на ноду |
| `04-ring-weights` | кольцо на 256 точек, у wallet-4 вес 2 |
| `05-ring-256` | кольцо на 256 точек, равномерная нагрузка |
| `05-hot-keys` | тот же кластер, только нагрузка: горячие пользователи на чтение и запись и мерчант |
| `06-ring-5` | то же кольцо, добавлена пятая нода, пользователи переносятся на неё без потерь |

## Как пользоваться

Переключиться на сценарий:

```bash
task scenario -- 01-mod-3
```

Команда поднимает процессы из `compose.yaml` и применяет `topology.json`, если он есть. Если набор процессов не изменился, контейнеры не перезапускаются: данные в нодах остаются, меняется только топология.

Нагрузка включается отдельно, когда данные уже загружены:

```bash
task load:apply -- 01-mod-3
```

Монолит с нуля:

```bash
task data
task scenario -- 00-monolith
task import -- http://localhost:9001
task load:reload
task load:apply -- 00-monolith
```

Сценарий на чистых данных — одной командой:

```bash
task fresh -- 01-mod-3
task load:apply -- 01-mod-3
```

`task fresh` поднимает сценарий, ставит нагрузку на паузу, перезапускает ноды (они хранят данные в памяти и поднимаются пустыми), раскладывает снапшот по новой топологии и перечитывает книгу loadgen. Нагрузка после этого стоит на паузе: `task load:apply -- <сценарий>` включает профиль сценария, `task load:set -- running=true` — прежний.

`task scenario` без `fresh` меняет только топологию, данные остаются где были. Так видно, что происходит с данными, если сменить топологию без переноса: `02-mod-4` после `01-mod-3`, `03-ring-4` после `03-ring-3`.

Перенос с `"migrate": true` запускается тоже через `task scenario`. Повторить перенос на пятую ноду: вернуть кластер на четыре ноды на чистых данных и перенести заново.

```bash
task fresh -- 05-ring-256
task load:apply -- 05-hot-keys
task scenario -- 06-ring-5
```

Переключение сценариев не пересобирает образы. После изменений в коде сервисов:

```bash
task build
```

Остановить всё:

```bash
task down
```
